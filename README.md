# VystWorld — сайт Minecraft-сервера

Исходный проект сайта для Minecraft-сервера Purpur 1.21.11: `vystworld.aternos.me`.

## Что включено
- Главная страница и адаптивный магазин на русском языке.
- Регистрация и вход через Supabase Auth (email/пароль и Google OAuth).
- Личный кабинет, история заказов, готовые аватарки и цветовые темы.
- Закрытая админ-панель: список аккаунтов и журнал успешных входов (IP/время/браузер).
- Серверное создание платежей YooKassa и проверка webhook через API YooKassa.
- SQL-схема Supabase с Row Level Security.
- Исходники экспериментального Paper/Purpur bridge-плагина для доставки заказов.

**Это стартовый проект, а не готовый опубликованный сервис.** Сначала настрой аккаунты провайдеров, секреты, цены/команды, юридические страницы и протестируй весь процесс.

## Запуск локально
1. Установи Node.js 20+ и Git.
2. Скопируй `.env.example` в `.env.local`.
3. Создай проект Supabase и заполни значения Supabase в `.env.local`.
4. В Supabase Dashboard → SQL Editor выполни `supabase/schema.sql`, затем `supabase/account-features.sql`.
5. В папке проекта выполни `npm install`, затем `npm run dev`.
6. Открой `http://localhost:3000`.

## Supabase: email и Google
1. В Supabase Dashboard → Authentication → URL Configuration укажи Site URL и Redirect URLs для локального сайта и будущего домена.
2. В Authentication → Sign In / Providers включи Google.
3. В Google Cloud Console создай OAuth client типа Web application и добавь redirect URI, показанный в настройках Supabase (обычно `https://<project-ref>.supabase.co/auth/v1/callback`).
4. Укажи Google Client ID и Client Secret в настройках Google provider в Supabase. Не помещай секрет Google в клиентский код.
5. Настрой SMTP и подтверждение почты для email/password регистрации.

Документация: https://supabase.com/docs/guides/auth/social-login/auth-google

## Админ-панель и журнал входов
1. В Vercel → Settings → Environment Variables задай `ADMIN_EMAIL` как точный email администратора.
2. Задай `SUPABASE_SERVICE_ROLE_KEY` серверным секретом (не добавляй префикс `NEXT_PUBLIC_` и никогда не публикуй его).
3. Выполни `supabase/account-features.sql` в Supabase SQL Editor. Журнал входов не имеет клиентских RLS-политик и читается только сервером.
4. После входа открой `/admin`. Список аккаунтов показывает до 100 пользователей за раз, журнал — последние 200 успешных входов. IP записывается только если хостинг передаёт `x-real-ip`; неудачные попытки входа не журналируются.
5. Добавь страницу политики конфиденциальности и сообщи пользователям о сборе IP-адресов. IP — персональные данные; ограничь срок хранения и доступ.

## YooKassa
1. Создай/настрой магазин YooKassa и получи shop ID и API secret.
2. Укажи на сервере `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`. Не используй префикс `NEXT_PUBLIC_` для секретов.
3. Укажи `NEXT_PUBLIC_SITE_URL` на HTTPS-домен и `YOOKASSA_RETURN_URL` как `https://YOUR-DOMAIN/payment/return`.
4. В кабинете YooKassa настрой webhook `https://YOUR-DOMAIN/api/payments/webhook` для события `payment.succeeded`.
5. Сначала тестируй с тестовым магазином. Обработчик webhook перепроверяет платёж прямым запросом к YooKassa.
6. До приёма реальных денег проверь требования к продавцу, чекам/налогам, возвратам, условиям продажи и применимым правилам. Если нужен взрослый владелец договора, попроси родителя/опекуна помочь с этим.

Документация: https://yookassa.ru/developers

## Minecraft bridge
1. В переменных окружения сайта установи `MINECRAFT_BRIDGE_SECRET` — случайный секрет длиной не менее 32 символов.
2. В `minecraft-plugin/src/main/resources/config.yml` укажи адрес сайта и тот же секрет. Не публикуй секрет.
3. Проверь команды в `src/lib/catalog.ts`. Примеры предполагают группы LuckPerms `vip`, `premium`, `legend` и команды выдачи предметов; поменяй их под свои плагины.
4. Сборка плагина требует Java 21 и Maven: из каталога `minecraft-plugin` выполни `mvn package`.
5. Установка пользовательского JAR на Aternos может быть недоступна. Не рассчитывай, что bridge можно загрузить на Aternos; если нельзя, используй разрешённый вариант хостинга или выполняй заказы вручную.

**Важно:** bridge — прототип. Перед использованием протестируй его на тестовом сервере. Если команда выполнится, а подтверждение доставки не дойдёт до сайта, возможна повторная выдача при следующем опросе. Не включай автоматические продажи, пока не добавлена надёжная идемпотентность и не протестированы повторные запросы.

## Публикация на Vercel
1. Импортируй этот GitHub-репозиторий в Vercel.
2. Добавь переменные окружения из `.env.example` в настройках проекта Vercel.
3. Выполни deploy и укажи `NEXT_PUBLIC_SITE_URL` на HTTPS-домен, затем сделай redeploy.
4. Обнови URL-адреса в настройках Supabase и webhook/return URL в YooKassa.

Документация: https://vercel.com/docs/frameworks/full-stack/nextjs
